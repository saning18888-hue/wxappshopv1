# 原生小程序商城 · 新仓库 PRD

**版本**：V1.0（新仓库首版）  
**产品形态**：原生微信小程序（WXML/WXSS/JS）+ 自有服务器后端  
**部署环境**：Nginx 1.22.1、PHP 8.2.31、MySQL 5.7.40、phpMyAdmin 5.2  
**部署原则**：不使用微信云函数、云托管或云数据库；所有业务由自有服务器提供 API。  
**本地开发**：SQLite（免装 MySQL）→ 调通后切换 MySQL 正式部署。

> **背景说明**：本 PRD 面向**新建仓库**的原生小程序开发。已从现有仓库 `vxappshopv1` 完全跑通的**店铺概况**与**设计装修**两大模块中沉淀可复用能力，作为新仓库 MVP 的"已完成底座"，其余能力按 MVP 优先级规划。

---

## 1. 产品定位与目标

建设一套可持续扩展的 B2C/O2O 微信小程序商城，使用**原生小程序**开发（不依赖跨端框架与云开发运行时），覆盖商品展示、购物流程、订单履约、会员运营与可视化店铺装修。

### 1.1 核心目标（新仓库 MVP）

1. **原生开发**：全部小程序端用原生 WXML/WXSS/JS 编写，零跨端框架依赖。
2. **店铺概况 + 设计装修先行复用**：直接沿用已跑通的"概况/设计装修"模块，作为新仓库的基础底座。
3. **闭环跑通**：浏览 → 购物车 → 下单 → 支付 → 履约 → 售后。
4. **服务器化部署**：本地 SQLite 调试 → 服务器 MySQL 正式上线（同 README 环境）。
5. **设计规范传承**：沿用现有 `UI设计规范.md` 的设计 Token、组件规范与交互红线。

### 1.2 与现有仓库的关系

| 维度 | 现有仓库 `vxappshopv1` | 新仓库 |
|---|---|---|
| 前端 | 原生小程序（已含完整交易闭环） | 原生小程序（重新组织，MVP 聚焦核心） |
| 后端 | ThinkPHP 8 + SQLite/MySQL | 同技术栈（迁移/复用已验证接口） |
| 店铺概况 | ✅ 已跑通 | 🟢 MVP 直接保留 |
| 设计装修 | ✅ 已跑通（轮播/魔方导航/精选推荐/分类导航/通知/广告位/首页布局/底部导航） | 🟢 MVP 直接保留 |
| 商品/订单/会员 | 已实现 | 🔶 MVP 按优先级重建 |
| 设计规范 | Airbnb 风格 V2.0 + UI 规范 | 原样传承 |

## 3. 已跑通模块（MVP 底座，直接复用）

### 3.1 店铺·概况（✅ 完全跑通，保留）

**菜单路径**：店铺 → 概况 → 运营概览

- 顶部指标卡（今日/本周/本月切换）：
  - 总金额、总订单、待付款、待发货、待售后
- 流量指标表：
  - 新用户数、访问人数、访问人次、打开次数、次均停留时长、跳出率（今日/昨日对比）
- 趋势图：
  - 新用户数、访问人数双指标折线图（Canvas 渲染，可勾选展示）
- 数据模块（数据 → 商城概况）：
  - 时间筛选（今天/昨天/最近7天/最近30天/自定义，最大30天）
  - 指标卡（金额/订单/转化率等）
  - 趋势图
- 数据模块（数据 → 交易分析）：交易漏斗、各环节转化率
- 数据模块（数据 → 商品分析）：商品浏览/访客/付款人数/金额/件数/转化率
- 数据模块（数据 → 网站分析）：指标卡 + 趋势图 + 新老访客 + 着陆页TOP10

### 3.2 店铺·设计装修（✅ 完全跑通，保留）

**菜单路径**：店铺 → 设计装修

| 模块 | 功能 |
|---|---|
| 轮播设置 | 首页轮播图配置：图片、链接（商品/分类/活动/文章）、排序、发布 |
| 魔方导航 | 金刚区图标导航：图标、文字、链接、列数配置 |
| 精选推荐 | 商品组模块：模块标题、列数（2列默认）、商品多选、独立拖拽排序、上/下架 |
| 分类导航 | 首页分类入口：分类图标、链接、排序 |
| 通知公告 | 多条公告增删、样式切换、排序 |
| 广告位 | 广告位名称、展示标题、多张广告图、拖动排序、单独下架 |
| 首页布局 | 拖拽模块调整首页从上到下的顺序；添加推荐模块/广告位 |
| 底部导航 | 菜单项（图标/名称/链接）增删改、拖拽排序（最少2最多5）、样式预留 |

**装修交互机制**：
- 所有装修操作均支持「保存草稿 → 发布上线」两阶段
- 发布后小程序端即时生效（通过 `/api/v1/home` 下发 JSON 配置）
- 后端保留版本历史，支持一键回滚
- 首页布局支持模块级独立上/下架，运营不改代码即可调整首页结构

## 4. 设计规范（原样传承）

### 4.1 设计语言

沿用 Airbnb 风格（温暖 · 图片优先 · 圆角卡片 · 单一强调色 · 杂志式留白），按微信小程序 `rpx` 体系落地。详见 `UI设计规范.md` 与 `PRD_B2C微信小程序商城_V2.0_设计驱动版.md`。

### 4.2 设计 Token（后端=紫色 `--primary:#5e6ad2`；小程序=橙色 `#FF6B35`，可配置化）

```css
/* 小程序端主色（默认，可后台配置换肤） */
--brand: #FF6B35;
--brand-press: #E85D2A;
--brand-tint: rgba(255,107,53,.08);

/* 后台主色（紫色，Linear 风格） */
--primary: #5e6ad2;
--primary-700: #4955b5;

/* 文字 */
--text: #222222;           /* 暖近黑，非纯黑 */
--text-secondary: #6A6A6A;
--text-disabled: rgba(0,0,0,.24);
--text-link: #428BFF;

/* 面 / 表面 */
--bg: #FFFFFF;
--surface: #F7F7F8;
--surface-2: #F2F2F2;
--line: #EBEBEB;

/* 状态 */
--success: #00B86B;
--error: #C13515;
--warning: #FFB400;
```

### 4.3 字号层级（小程序端，八档收敛）

| 角色 | 尺寸(rpx) | 字重 | 用途 |
|---|---|---|---|
| 页面大标题 | 56 | 700 | 区块标题、详情商品名 |
| 区块标题 | 44 | 600 | 金刚区/商品组标题 |
| 卡片标题 | 40 | 600 | 商品名、列表卡 |
| 强调文本 | 32 | 500 | 导航、按钮、Tab |
| 正文/链接 | 28 | 400 | 标准正文 |
| 次要描述 | 26 | 400 | 副标题、说明 |
| 标签/价格 | 24 | 400–700 | Tag、角标、价格 |
| 微标 | 22 | 600 | 状态徽章 |

### 4.4 圆角与阴影

- 圆角等级：8（微）→ 16（标准）→ 28（徽章）→ 40（卡片）→ 64（大容器）→ 50%（圆）
- 卡片三层暖光阴影：`rgba(0,0,0,.02) 0 0 0 1rpx, rgba(0,0,0,.04) 0 4rpx 12rpx, rgba(0,0,0,.10) 0 8rpx 16rpx`
- **红线**：强调色只用于 CTA；禁止纯黑文字；标题禁止细字（<500）；禁止锐角卡片（<16rpx）；颜色只用 token，禁止硬编码。

### 4.5 后台 UI 规范

- 弹窗关闭按钮统一圆形灰底 `class="close"`
- 删除确认统一 `confirmDialog()`
- 多选勾选项用原生 checkbox + `accent-color:var(--primary)`
- 二选一项用分段控件 `.a-seg`（禁止裸 radio）
- 文字标签与控件/图标间必须有 ≥8px 间距
- 改 JS 后必须 `node --check` 校验

## 6. 后端技术架构

### 6.1 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 语言 | PHP 8.2 | 目标服务器 PHP 8.2.31 |
| 框架 | ThinkPHP 8 | 与现有仓库一致 |
| 数据库 | MySQL 5.7（生产）/ SQLite（本地） | 本地免装 MySQL 快速调试 |
| Web 服务器 | Nginx 1.22.1 | 伪静态指向 `server/public` |
| 管理后台 | 单文件 SPA（admin.html） | 全部 JS/CSS 内嵌，`X-Admin-Token` 鉴权 |

### 6.2 本地开发环境（同现有仓库）

```bash
cd server
composer install                    # 无 composer 时先装
php database/init_sqlite.php        # 首次生成 SQLite + 种子
cp .env.example .env                # 默认 DB_DRIVER=sqlite
php think run -H 127.0.0.1 -p 8899  # 端口约定 8899
```

- 小程序 API：`http://127.0.0.1:8899/api/v1`
- 运营后台：`http://127.0.0.1:8899/admin.html`（默认 `admin` / `admin123`）
- 小程序：导入 `miniprogram/`，`config.js` 设 `useMock:true` 可免后端体验；`useMock:false` + `baseUrl` 联调真实后端

### 6.3 生产部署（同现有仓库）

```bash
cd server && composer install && cp .env.example .env
mysql -u root -p < database/install.sql
# Web 根目录指向 server/public，配置伪静态去掉 index.php
```

## 7. 数据表规划

沿用现有仓库已验证的建表脚本（`database/install.sql`），核心表：

```
用户与权限：users、user_profiles、user_addresses、admin_users、roles、permissions、admin_logs
商品：goods、goods_skus、goods_specs、goods_spec_values、categories、goods_media、inventory_logs
交易：carts、orders、order_items、order_payments、order_logs、refunds、after_sales、shipments

内容装修：pages、page_versions、page_components、articles、banners、media_files
门店配送：stores、pickup_codes、delivery_rules、shipping_templates
```

所有金额使用整数分或 DECIMAL，库存操作必须有流水；订单、支付回调、退款回调不得依赖单一请求成功。

## 8. 微信能力接入

- AppId/AppSecret 仅保存在服务端环境变量中，不进入小程序包
- 微信登录由服务端换取用户身份并建立会员绑定
- 微信支付统一由服务端创建支付参数、验签处理回调、查询订单和发起退款
- **当前阶段**：登录/支付为 Mock 模拟（结构预留真实接口），后续在 `.env` 填 `WECHAT_APPID/APPSECRET/MCH_ID/MCH_KEY/NOTIFY_URL` 后切换真实模式

## 9. MVP 验收标准

1. 新用户可从小程序登录，浏览商品并选择 SKU 下单。
2. 服务端能正确计算商品、运费、优惠券、积分和实付金额。
3. **店铺·概况**：今日/本周/本月指标卡 + 流量表 + 趋势图均正确展示，数据实时准确。
4. **店铺·设计装修**：运营人员可不改代码配置轮播/魔方导航/精选推荐/分类导航/通知/广告位/首页布局/底部导航，支持保存草稿、预览、发布、回滚。
5. 微信支付成功后，无论回调重复、延迟或用户返回，小程序和后台最终状态一致。
6. 快递订单可发货并保存物流单号；自提订单可生成取货码并完成核销。
7. 用户可取消未支付订单、申请售后；后台可审核并形成退款记录。
8. 未授权管理员不能访问后台数据；关键操作有日志；数据库可备份并恢复。
9. **设计一致性**：全站色值仅来自 Design Token，无硬编码色；强调色未大面积铺底。
10. **字号可读性**：正文 ≥28rpx、标签 ≥22rpx；后台弹窗主/次文 14/13px 且控件继承字号。
11. **卡片规范**：商品/内容卡均为大圆角 + 三层阴影；无锐角卡片、无纯黑文字。
12. **换肤可行**：仅改 Design Token 即可整体换色/换圆角，业务代码零改动。
13. 在目标服务器完成部署（Nginx 1.22.1 + PHP 8.2.31 + MySQL 5.7.40），使用正式域名 HTTPS，完成真机调试和主要流程测试。

## 11. 风险与注意事项

- **不要重复造轮子**：概况/设计装修已跑通，优先迁移复用，避免重写引入回归。
- **设计规范是资产**：所有新页面必须遵循 `UI设计规范.md` 的 Token/组件/红线，不得硬编码。
- **本地优先**：先 SQLite 本地调通，再切 MySQL 正式部署；`.env` 配置分离。
- **Mock 与真实微信**：MVP 阶段可用 Mock，但接口结构预留真实微信登录/支付，避免后期返工。
- **版本与文档同步**：发版必须同步更新 `CHANGELOG.md` 与 `git tag`。
